## Исходный проект

В проекте уже реализованы:

- интерфейс `BaseAnalogClock`;
- класс `AnalogClock`, хранящий время как положение стрелок и признак `AM/PM`;
- интерфейс `BaseDigitalClock`, с которым должен работать клиентский код;
- `ClockFormatter` для форматирования времени;
- `ClockHistory` для хранения истории установленных значений;
- пример клиентского компонента `DigitalClockDisplay`.

## Важное требование

Adapter и Facade решают разные задачи.

- **Adapter** преобразует один интерфейс в другой.
- **Facade** предоставляет более простой интерфейс к подсистеме.

Не следует объединять их в один класс только потому, что оба используются в одной лабораторной работе.

## Описание решения

### Adapter - `DigitalClockAdapter`

Назначение адаптера - позволить клиентскому коду работать с аналоговыми часами
через цифровой контракт `BaseDigitalClock`: адаптер реализует его, а внутри
обращается к часам по интерфейсу `BaseAnalogClock`. Адаптер объектный: он хранит
ссылку на часы, а не наследуется от них.

Положение каждой стрелки считается по делениям циферблата: стрелка стоит ровно
на делении своей единицы времени и перескакивает на следующее при её смене -
в отличие от обычных часов, где стрелка движется плавно от одного значения
к другому.

| Стрелка | Положение |
|---|---|
| часовая | `(час % 12) × 30°` |
| минутная | `минуты × 6°` |
| секундная | `секунды × 6°` |

Часть суток: до 12 часов - `AM`, с 12 - `PM`.

Обратное преобразование симметрично: каждая единица времени читается из своей
стрелки (`угол / 6` - минуты и секунды, `угол / 30` - час), флаг `PM` добавляет
12 часов. Доли секунды циферблатом не выражаются, поэтому микросекунды
округляются до ближайшей секунды, при переполнении - с переносом
(`12:00:59.700` -> `12:01:00`).

Краевые случаи: полночь и полдень дают одинаковое положение стрелок `0°/0°/0°`
и различаются только флагом (`AM` -> час 0, `PM` -> час 12); `23:59:59` -
`330°/354°/354°`, ни одна стрелка не доходит до «12».

### Facade - `ClockFacade`

Назначение фасада - единый интерфейс к подсистеме часов: клиент выполняет одну
операцию вместо нескольких обращений к адаптеру, форматтеру и истории по
отдельности. Фасад - оркестратор, управляющий элементами, обладающими своей
бизнес-логикой: формулы живут в адаптере, форматирование - в `ClockFormatter`,
хранение истории - в `ClockHistory`.

Клиенту доступны четыре операции:
1. установить дату-время,
2. получить дату-время,
3. получить форматированное представление,
4. получить историю изменений.

### Разница между адаптером и фасадом

Adapter и Facade решают разные задачи: Adapter преобразует интерфейс одного
компонента под ожидания клиента, Facade скрывает подсистему за единым
интерфейсом, беря на себя всё взаимодействие с её компонентами.

Структурная диаграмма итоговой реализации адаптера и фасада в [docs/README.md](docs/README.md).

### Тест-кейсы

**Установка времени через адаптер**

- **Установка раскладывает время в углы и флаг** - (параметризация: обычный случай + крайние) вызвать у адаптера установку входного значения -> проверить углы, флаг и дату `2026-09-24`:
  - `15:30:45` -> `90°/180°/270°`, PM - обычное время;
  - `00:00:00` -> `0°/0°/0°`, AM - полночь: стрелки на «12», но это начало суток;
  - `12:00:00` -> `0°/0°/0°`, PM - полдень: позиция как у полуночи, различие только флагом;
  - `11:59:59` -> `330°/354°/354°`, AM - час до полудня;
  - `23:59:59` -> `330°/354°/354°`, PM - последняя секунда суток, круг не докручен;
- **Доли секунды округляются до целой** - вызвать у адаптера установку `2026-09-24 12:00:00.700` -> проверить, что у обёрнутых часов углы `0°/0°/6°`, PM - состояние соответствует `12:00:01`.
- **Округление переносится в минуту** - вызвать у адаптера установку `2026-09-24 12:00:59.700` -> проверить, что у обёрнутых часов углы `0°/6°/0°`, PM - состояние соответствует `12:01:00`.

**Получение времени через адаптер**

- **Углы из часов читаются как время** - (параметризация: обычный случай + крайние) записать в аналоговые часы дату `2026-09-24`, углы и флаг -> обернуть часы адаптером и вызвать чтение -> проверить, что адаптер вернул ожидаемое время:
  - `90°/180°/270°`, AM -> `03:30:45` - обычное время;
  - `0°/0°/0°`, AM -> `00:00:00` - полночь;
  - `0°/0°/0°`, PM -> `12:00:00` - полдень;
  - `330°/354°/354°`, AM -> `11:59:59` - час до полудня;
  - `330°/354°/354°`, PM -> `23:59:59` - последняя секунда суток.

**Цикл установки и чтения через адаптер**

- **Цикл установки и чтения не теряет информацию** - создать адаптер -> вызвать установку `2026-09-24 12:34:56`, затем чтение -> возвращён тот же момент.

**Операции через фасад**

- **Время, установленное через фасад, то же при чтении** - создать фасад -> вызвать установку `2026-09-24 15:30:45`, затем чтение -> проверить, что возвращён тот же момент.
- **Формат по умолчанию даёт строку «дд.мм.гггг чч:мм:сс»** - установить `2026-09-24 12:34:56` -> запросить форматированное представление -> проверить, что получено `24.09.2026 12:34:56`.
- **Пользовательский формат соблюдается** - запросить форматированное с шаблоном `%Y-%m-%d` -> проверить, что получено `2026-09-24`.
- **История накапливает установки по порядку** - выполнить три установки подряд -> запросить историю -> проверить, что получены те же три значения в порядке выполнения.
- **Чтение и форматирование историю не пополняют** - после одной установки дважды прочитать и один раз отформатировать -> проверить, что в истории одна запись.
- **История наружу неизменяема** - запросить историю -> попытка изменить элемент отклоняется (кортеж) -> повторный запрос возвращает те же данные.

**Работа клиентского дисплея с адаптером**

- **Готовый клиент получает время из адаптера** - создать адаптер и дисплей -> установить время через адаптер -> дисплей вернул строку `2026-09-24 15:30:45` в своём формате.
